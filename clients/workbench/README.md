# 本机工作台（Fork 实验版）

这是独立的 HTTP 客户端，不是新的调度内核。可以查看运行、回答卡片，也可以沿用本机预先配置的规则新建任务对话、发送需求、查看最终回复并继续讨论。调度和运行状态仍来自中台 API；没有运行时依赖，不需要前端构建。

## 启动

需要 Node.js 24 或更新版本，以及已经安装、登录好的命令行 Agent。支持 Linux、macOS；Windows 请在 WSL2 内运行，暂不支持原生 Windows。WSL2 的服务和通知限制见 [INSTALL](../../INSTALL.md)。

**这个功能需要本 fork 的源码。** 上游安装器与 `agent-autoloop update` 仍安装上游 Release，不包含工作台或新的回复保存逻辑。仅启动这里的页面、继续使用旧 worker，只能看到摘要，不能补出旧轮次的完整回复。

### 首次从源码启动

以下命令都在本 fork 的源码根目录运行。示例选择已登录的 Codex，也可以将 `--agent codex` 换成 `--agent claude`。新数据目录用于与已有安装分开；不要在同一个目录重复初始化。

```sh
# 终端一：只在尚未初始化的新目录执行 init。
export AGENT_AUTOLOOP_HOME="$HOME/.agent-autoloop-workbench"
node bin/agent-autoloop.ts init --agent codex --no-service

# codex 必须是 rules.json 中已有的 Agent 编号。
# 把 /absolute/path/to/project 换成真实存在的项目目录。
npm run workbench:chat -- --name "项目对话" --agent codex --cwd /absolute/path/to/project
node bin/agent-autoloop.ts check

# 保持运行：启动此源码版本的中台、worker 和已配置的通道。
node bin/agent-autoloop.ts up
```

```sh
# 终端二：同一源码目录、同一个数据目录。
export AGENT_AUTOLOOP_HOME="$HOME/.agent-autoloop-workbench"
npm run workbench
```

打开终端打印的 `http://127.0.0.1:4318`，在“任务对话”中选择“项目对话”，点“新建对话”，再输入需求。端口被占用时用 `npm run workbench -- --port 4319`。按 Ctrl+C 关闭工作台不影响中台和正在运行的 Agent；关闭运行 `up` 的终端则会停止相应服务。

### 使用已有配置

默认数据目录是 `~/.agent-autoloop`。若使用 `AGENT_AUTOLOOP_HOME`，配置命令、中台、worker、工作台都必须指向同一个目录；设置过 `AGENT_AUTOLOOP_RULES` 时也要一致。不要复制密钥到浏览器。

- 工作台启动必须有 `config.json` 中的 `url`、`owner`。只有 worker 配置、没有本人密钥的电脑不能启动页面。
- 开通对话还需要本机 `hub` 配置、`source.name` 和 `source.key`，且该来源已登记在 `rules.json` 中。没有这些时仍可查看状态、回答卡片，但不能发送对话消息。
- 执行任务需要规则指定的 Agent 和对应 worker 在线。要显示完整最终回复，需要本 fork 更新后的本机 worker，与工作台共用数据目录，且配置中的 worker 名称与该轮实际执行者一致。
- 不要再次运行 `init` 覆盖已有安装。先确认现有规则和 Agent，再运行下面的开通命令。若需要切换到源码版 `up`，先停止同一数据目录下原有的中台/worker 服务，避免两个实例同时运行；不要把测试实例接入已在线的同一通道监听。

```sh
npm run workbench:chat -- --name "项目对话" --agent EXISTING_ID --cwd EXISTING_PATH
```

`EXISTING_ID` 替换为 `rules.json` 的 `agents` 中已有的编号；`EXISTING_PATH` 替换为已存在的绝对目录，或引号内的 `~/项目路径`。路径含空格时加引号。

这个命令只在本机新增一条固定规则：使用现有 source，固定 Agent、真实项目目录和提示词，设置 `resume: true`、`parallel: 1`。它不创建密钥，不改 Agent 的命令、权限或其他规则。写入前校验完整规则并保存原文件备份，拒绝同名规则、无效 Agent/目录以及会重复匹配对话事件的通配符规则；不会覆盖已有同名规则。

修改完成后，按命令提示重启 worker 和工作台，使目录白名单与入口生效；中台仍按原机制加载规则。前台源码运行可先停止 `up` 和工作台，再分别运行 `node bin/agent-autoloop.ts up`、`npm run workbench`。页面不会替你执行配置命令，也不能填写任意 Agent、命令、目录或权限。

## 任务对话怎么工作

- 新建对话只选择已经生效、没有匹配冲突的对话规则。每段对话有独立事项标识，消息通过现有 `POST /v1/events` 送进中台，正文是事件资料，不是可信规则或 shell 命令。
- 单条消息最多 4000 字。同一对话有轮次排队、执行或状态未知时不能再发；开通命令生成的规则以 `parallel: 1` 限制同一规则下的对话，按中台调度串行处理。不同对话不会因为共用规则而共用同一个事项。
- 任务对话会显示消息、轮次状态、运行编号、最终回复或明确标注的摘要。可以按轮次编号在运行列表查详情，再从关联运行详情回到对话。页面定时刷新，**没有流式输出、终端输出或逐步工具日志**。
- 本 fork 的 worker 保存 Agent 最终业务文字的本地副本，去掉 `agent-autoloop` 回执代码块，不把原始 stdout/stderr 当回复展示。工作台只为核对过的已结束轮次读取这个副本。超长输出可能截断，页面会明确提示。
- 旧 worker、远端 worker、已清理或无法核对的输出只有运行摘要，页面会显示“完整回复不可用”，不会把一句摘要冒充完整答复。没有本地副本的旧历史不能追溯补齐。
- `resume: true` 表示中台和支持续接的 Agent 插件尽量使用实际返回的会话编号接续；页面显示记录到的会话情况。Agent 不支持续接、旧会话不可用或调度保护触发时可能开新会话，**不保证永久保留模型上下文**。页面留有聊天记录不等于 Agent 会重新收到全部历史。
- 有待回答的 `ask` 卡片时，先到“待你回答”选择或填写答案并明确提交，不能在聊天里写“同意”代替卡片回答。普通卡片也不是绑定 Spec、Plan 文件版本或提交 SHA 的审批。

### 记录与异常恢复

发送前会把消息和稳定编号保存到本机。响应丢失时，页面保留“送达结果未确认”状态，先刷新核对，再用“核对并重试这条原消息”；不要另发一条相同内容。重试保留原消息编号，由中台去重。规则变化、路由冲突、历史未完整核对或仍有待确认结果时，页面会说明原因并暂停发送。

对话消息、关联轮次和已读取的回复缓存在 `$AGENT_AUTOLOOP_HOME/workbench/chats/`，重启工作台后仍可读。未发送草稿只留在当前页面，刷新或关闭页面可能丢失。worker 的回复副本位于数据目录的 `worker/runs/`，随轮次输出按原有 14 天策略清理；工作台已缓存的回复没有同样的自动过期机制。请把这些目录当作私人对话和项目资料保管。缓存不是模型会话备份，也不是中台权威状态。

## 原有运行看板

- 查看规则任务与真实运行记录，按任务、状态和文字筛选，加载更早的运行。
- 查看每轮结论、错误、时间、事件与事实时间线。
- 查看待确认卡片，选择选项或填写自己的回答，明确点击提交后交回中台。
- 查看最近的卡片回答和结案状态。Agent 在线详情与用量统计仍使用原有 `agent-autoloop status` 查看。

断开时保留旧数据并明确提示；旧数据不是当前状态。卡片回答响应丢失时不要盲目再提交，先刷新卡片状态；中台原有去重仍生效。

**状态的含义不变：** `done` 只表示本轮结束，可能还有待回答的问题。`queued` 是排队或等待重试，`unknown` 表示运行状态不明。规则列表仍来自中台配置；运行列表第一页含全部活跃轮次以及最近 60 轮，筛选只覆盖已经加载的记录。

**还没有：** 浏览器内规则编辑或任意 Agent 配置、Spec / Plan 文档管理、版本绑定审批、Coding / Review 阶段编排、GitHub 管理、停止任务、合并、部署按钮。任务对话会按既有规则启动真实 Agent，使用其现有权限和模型额度；页面不会因此增加权限，也不提供额外沙箱。配置提示词要求未经明确授权不得 push、merge 或 deploy，这不替代 Agent 自身的权限控制。

## 安全边界

- 页面服务强制只监听 `127.0.0.1`，仅供本人本机使用。不要通过反向代理、端口转发或公网隧道共享它；本版没有多人登录或授权系统。
- 本人密钥和来源密钥只在 Node 进程中读取，用于访问现有配置指定的中台。不返回页面、不放 URL 或浏览器存储，不记录到日志。中台重定向不会被跟随。
- 本人请求限于 `GET /v1/state`、`GET /v1/runs/:id/why` 和 `POST /v1/cards/:id/answer`。对话接口另外使用来源密钥向 `POST /v1/events` 提交服务端构造的固定路由事件，不提供通用事件代理或任意文件读取。
- 校验 Host、Origin 和请求头，拒绝跨站请求；不开放 CORS，禁止页面被嵌入。外部标题、正文、回复和日志按文字显示。
- 本机规则和配置是可信配置。浏览器只选择规则并提交消息，不能修改 Agent、命令、目录、来源或权限。路由预检不锁定规则版本；在本机修改规则可能影响尚未领取的轮次，实际规则版本仍以运行详情中的事实记录为准。聊天内容仍可能含提示注入，不要把固定路由误认为能防止 Agent 的所有越权操作。
- 对话以本机文件保存，目录创建权限为 `0700`、文件为 `0600`。回复中的当前轮次 token 会被去除，但这不是通用秘密检测器，Agent 写进业务文字的其他敏感信息仍可能被展示和缓存。
- 这不是同机进程间的安全隔离。能使用同一系统账号或本机端口的其他程序仍可能访问数据、发任务和回答卡片。不要在不受信任的多人电脑上运行。
- 不会额外限制现有 Agent 权限。发送对话消息或回答某张卡片可能唤醒后续轮次，请先读清楚内容。

## 验证

在源码目录可运行：

```sh
npm ci
node --disable-warning=ExperimentalWarning --test tests/workbench.test.ts tests/workbench-chat.test.ts tests/workbench-chat-e2e.test.ts tests/workbench-setup.test.ts tests/worker-reply.test.ts
npm run test:quick
npm run typecheck
npm run format:check
```

相关测试使用临时数据目录、随机本机端口和测试 Agent，通过真实中台 API 检查读取、回答、对话事件、重复提交、规则配置、历史恢复及回复保存，并检查跨站防护、接口边界与故障响应。它们不使用真实模型账号、不发外部消息，不等于已经验证所有真实 Agent、浏览器或 Windows 环境；具体通过情况以本次运行结果为准。
