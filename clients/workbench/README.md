# 本机工作台（Fork 实验版）

这是独立的 HTTP 客户端，不是新的调度内核。沿用中台的规则、状态、事件记录和回答机制，没有运行时依赖，也不需要前端构建。

## 启动

需要 Node.js 24 或更新版本，以及已经初始化并运行的 Agent Autoloop。请在有本人配置的电脑上运行：

```sh
# 在本 fork 的源码目录中。中台仍按原来的方式启动。
npm run workbench
```

打开终端打印的 `http://127.0.0.1:4318`。端口被占用时用 `npm run workbench -- --port 4319`。按 Ctrl+C 关闭工作台不影响中台和正在运行的 Agent。

工作台读取 `~/.agent-autoloop/config.json` 的 `url` 和 `owner`；使用其他安装目录时设置 `AGENT_AUTOLOOP_HOME`。只读现有配置，不创建密钥、不修改规则、不启动中台或 Agent。只有 worker 配置、没有 owner 密钥的电脑不能启动工作台。首次安装参见仓库的 [INSTALL](../../INSTALL.md)，不要把密钥复制进浏览器。

上游安装器与 `agent-autoloop update` 仍安装上游 Release，不包含这个 fork 的页面。当前从本 fork 的源码单独启动工作台，不替换你已有的安装。

## 第一版能做什么

- 查看规则任务与真实运行记录，按任务、状态和文字筛选，加载更早的运行。
- 查看每轮结论、错误、时间、事件与事实时间线。
- 查看待确认卡片，选择选项或填写自己的回答，明确点击提交后交回中台。
- 查看最近的卡片回答和结案状态。Agent 在线详情与用量统计仍使用原有 `agent-autoloop status` 查看。

每隔一段时间读取最新状态，也可以手动刷新。断开时保留旧数据并明确提示；旧数据不是当前状态。回答响应丢失时不要盲目再提交，先刷新卡片状态；中台原有的卡片去重仍生效。

**状态的含义不变：** `done` 只表示本轮结束，可能还有待回答的问题。`queued` 是排队或等待重试，`unknown` 表示运行状态不明。任务列表来自规则，不是新建的项目管理系统；第一页含全部活跃轮次以及最近 60 轮，筛选只覆盖已经加载的记录。

**还没有：** 任务创建、规则编辑、Spec / Plan 文档管理、绑定文件版本或提交 SHA 的审批、Coding / Review 阶段编排、GitHub 操作、停止任务、合并、部署。普通卡片回答不能证明某个版本的 Spec 或 Plan 已批准。工作台不会自动执行这些操作。

## 安全边界

- 页面服务强制只监听 `127.0.0.1`，仅供本人本机使用。不要通过反向代理、端口转发或公网隧道共享它；本版没有多人登录或授权系统。
- 本人密钥只在 Node 进程中读取，用于访问现有配置指定的中台。不返回页面、不放 URL 或浏览器存储，不记录到日志。中台重定向不会被跟随。
- API 只允许 `GET /v1/state`、`GET /v1/runs/:id/why` 和 `POST /v1/cards/:id/answer`，不能作为其他本人接口的通用代理。
- 校验 Host、Origin 和请求头，拒绝跨站请求；不开放 CORS，禁止页面被嵌入。外部标题、正文和日志按文字显示。
- 这不是同机进程间的安全隔离。能使用同一系统账号或本机端口的其他程序仍可能访问数据和回答卡片。不要在不受信任的多人电脑上运行。
- 不会额外限制现有 Agent 权限。回答某张卡片可能唤醒后续轮次，请先读清楚卡片内容。

```sh
npm ci
node --disable-warning=ExperimentalWarning --test tests/workbench.test.ts
npm run test:quick
npm run typecheck
npm run format:check
```

集成测试使用临时数据目录和随机本机端口，通过真实中台 API 验证读取、回答、恢复和重复提交，并检查跨站防护、密钥不泄漏、接口白名单与故障响应。测试不使用真实账号、不发外部消息、不运行真实模型。
